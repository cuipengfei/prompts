# Uncharted

把实践中的模糊感受逐步变成三类知识：词汇、模式和模式语言。先让 AI 生成候选，再用资料与案例筛选；随后把适合自动执行的部分编成规则，通过执行结果继续修正知识。

## 适用场景

- 用户已经接触一个陌生领域，却缺少描述问题的语言。
- 用户能指出具体任务、失败产出或模糊不满，却说不清问题在哪里。
- LLM 的回答空泛、反复变化，结果难以解释和修正。
- 团队缺少共同词汇，同一个词经常指向不同事物。
- 用户想把经验整理成可复用的 prompt、system instruction、检查清单或 agent 规则。
- 已有规则经常冲突，需要检查词汇、模式、知识框架或执行条件。

## 先判断入口

先确认用户能提供哪一种实践依据：

- 一项正在完成的真实任务；
- 一个具体案例或失败产出；
- 一种可以观察到、但暂时说不清的感受。

有实践依据时进入本 skill。用户只有宽泛兴趣时，先收集代表性案例、领域资料和一个可观察结果的任务。材料不足时保留未知，不自行生成完整领域体系。

按当前目标选择工作方式：

| 当前目标                                  | 处理方式                                             |
| ----------------------------------------- | ---------------------------------------------------- |
| 查询一个明确事实                          | 使用 `investigation-first` 或 `multi-source-inquiry` |
| 建立当前项目的术语表、`CONTEXT.md` 或 ADR | 使用 `domain-modeling`                               |
| 已有假说，需要通过实践检验                | 使用 `practice-cognition`                            |
| 生成多 agent 研究系统                     | 使用 `POMASA`                                        |
| 从实践问题形成领域语言和执行规则          | 继续使用本 skill                                     |

高风险任务需要独立的专业审核和确定性验证。本 skill 只能帮助组织知识，不能替代医疗、法律、财务或安全责任。

## 方法的三个坐标

用三个坐标说明知识内容、学习过程和职责分配。

| 坐标     | 回答的问题     | 内容                                          |
| -------- | -------------- | --------------------------------------------- |
| 知识结构 | 要形成什么知识 | 词汇、模式、模式语言                          |
| 学习循环 | 知识怎样增长   | 实践问题、候选、核实、执行、观察、修正        |
| 职责边界 | 谁作出什么判断 | 人决定目的和取舍；AI 扩展候选、执行并暴露缺陷 |

三类知识产物：

| 层级     | 作用                             | 产出                                               |
| -------- | -------------------------------- | -------------------------------------------------- |
| 词汇     | 划分问题空间，给现象稳定命名     | 维度、术语、定义、正例、反例                       |
| 模式     | 记录反复出现的问题和可复用的响应 | 情境、问题、作用力、响应、后果、适用条件           |
| 模式语言 | 组织模式之间的关系               | 知识框架、证据标准、映射、降级、冲突仲裁、未知内容 |

执行规则是这些知识经过筛选后的可执行形式。它不等同于模式语言，也不要求所有经验都能规则化。

知识产物按下列关系逐步变化：

```text
模糊感受 → 可观察维度 → 有边界的词汇 → forces 与模式
→ 有来源的知识框架 → 执行规则 → 运行结果 → 知识修正
```

三层结构描述要形成什么，学习循环描述知识怎样增长，下面六项操作描述每次变化怎样完成。三者互相引用，但各自回答不同问题。

## 运行方式

把当前工作视为循环。首次进入陌生领域时，通常从实践问题开始；已有词汇、模式或规则时，从观察信号指向的位置继续。

知识增长循环：

```text
实践问题 → AI 生成候选 → 原始资料核实 → 提取词汇和模式
→ 编写执行规则 → AI 执行 → 根据产出修正知识 → 下一轮
```

六项构建操作依次是：划分问题空间、命名元素、识别 forces、核实原始资料、声明知识框架、编写执行规则。候选可以先于核实产生；正式词汇、模式、框架和规则只能使用已经核实的内容。

首次使用本方法，或无法判断各阶段产物是否合格时，读取 [`references/one-cycle-example.md`](references/one-cycle-example.md)。其他情况直接处理当前阶段。

## 建立词汇

### 划分问题空间

进入信号：用户能指出具体案例或模糊不满，但无法说明哪些方面造成问题。

操作：

1. 记录案例和用户当时要完成的任务。
2. 询问哪些现象引起不满，改变什么可能影响结果。
3. 让 AI 或资料提供候选维度，并标记为待核实。
4. 用其他案例检查维度是否遗漏、重叠或无法操作。

产物：一组可以分别观察和调整的问题维度。

通过条件：维度覆盖用户指出的主要问题，彼此含义可以区分，每个维度都有可观察信号或调整动作。

### 命名元素

进入信号：同一种现象、状态或策略反复需要一段话才能描述。为它建立稳定名称，优先采用领域已有术语。

操作：为每个词记录：

- 名称与定义；
- 包含范围与排除范围；
- 正例与反例；
- 所属维度；
- 来源状态。

LLM 提出的新词只算候选。参与者面对具体案例时，应能用同一个词指向同一种现象；出现分歧时继续收紧边界。

产物：一组可以直接进入问题陈述、模式和规则的词汇。

通过条件：名称可以直接引用；定义有包含与排除边界；相邻概念能够区分；新参与者根据定义可以正确使用；多个名称可以组成更完整的描述。

## 形成模式

进入信号：多个选择各有合理价值，并且当前无法同时充分满足。将这种反复出现的问题记录为包含可复用响应的模式。

操作：为每个模式记录：

- 情境：它在什么条件下出现；
- 问题：需要处理什么；
- 力量：各方分别保护什么；
- 响应：怎样处理这些力量；
- 后果：得到什么，同时付出什么代价；
- 边界：何时适用，何时失效；
- 来源状态：待核实、已核实、推断或未知；可另行注明是否来自已有领域模式。

明显错误归入缺陷。暂时不知道解法时标为知识缺口。只有两端都有合理需求、且当前无法同时充分满足时，才记录为力量冲突。

产物：一组说明情境、问题、forces、响应、后果和边界的模式。

通过条件：模式能说明适用情境、响应方式、收益、代价和失效条件。

## 设置证据门

进入信号：候选概念会改变框架、判断标准或执行规则，或者其来源尚未核实。

AI 可以搜索来源线索、整理候选解释和比较定义。人负责决定哪些证据可以进入知识体系。

不同来源承担不同职责：

| 来源 | 在本方法中的作用 | 能支持的判断 |
| ---- | ---------------- | ------------ |
| 实践经验 | 提供问题、forces 和结果反馈 | 问题是否存在、目的是什么、结果是否有用 |
| 原始资料 | 核实定义、前提和概念关系 | 概念是否有据可查 |
| LLM 输出 | 扩展候选和来源线索 | 只能形成待核实候选 |
| 运行结果 | 检查规则与案例是否匹配 | 规则是否需要修正，不能直接证明领域主张 |

分别记录来源职责和核实状态。运行成功只能说明规则适合已观察案例。

操作：对会改变框架、判断标准或执行规则的概念检查：

1. 谁提出或系统说明了它；
2. 原始资料怎样定义它；
3. 定义成立需要哪些前提；
4. 它与相邻概念有什么区别；
5. 同一知识体系怎样组织这些概念；
6. 是否存在互相冲突的学派、版本或实证结果。

记录四种来源状态：

- 待核实：来自 AI、二手材料或尚未检查的经验；
- 已核实：原始资料或可靠实证直接支持；
- 推断：由现有证据合理推出，原始资料没有直接表达；
- 未知：当前材料无法确认。

无法取得原始资料时，说明证据限制，并用多个独立资料和真实案例交叉检查。待核实和未知内容可以继续用于探索，但不得编入正式规则。

产物：带有来源、原始定义、成立前提和概念区别的核实记录。

通过条件：所有会改变框架或规则的关键概念都有来源状态和可定位依据。

## 组成模式语言

进入信号：多个模式需要共同工作，或同一问题存在不同知识体系、优先级和有效性标准。

操作：记录当前采用的知识框架，以及各模式怎样共同工作：

- 当前采用哪套知识体系及选择原因；
- 核心词汇和模式；
- 什么证据可以进入判断；
- 适用范围与未知内容；
- 多个目标或模式冲突时的仲裁原则。

为模式之间建立三类关系：

- 映射：一个模式的结果在什么条件下触发另一个模式；
- 降级：高层模式无法稳定执行时，使用哪项基础能力维持最低可接受结果；
- 一致性：多项要求同时作用时，如何发现冲突并按已声明的原则仲裁。

多套知识体系共同使用时，分别说明各自处理的问题、术语含义和冲突处理方式。

产物：能够指导模式选择、组合、降级和冲突处理的关系说明。

通过条件：每个模式都有适用位置；组合使用时能判断下一步、降级路径和冲突优先级。

## 编译执行规则

进入信号：知识已经核实，任务中的触发条件、动作和例外可以观察。

操作：只把适合自动执行的知识写成规则。常用结构：

```text
IF [可以观察的触发条件]
THEN [明确动作]
UNLESS [可以判断的例外]
```

把“合适”“自然”“高质量”“有高级感”等模糊形容词换成可观察条件。具体阈值只能来自用户、可靠资料或真实测试结果。

每条规则应能回答：

- 什么条件触发；
- 执行什么动作；
- 什么情况跳过；
- 依赖哪个词汇、模式和知识框架；
- 与其他规则冲突时怎样处理；
- 什么结果说明它需要修正。

保留需要人判断的内容。审美、伦理、人际关系、新问题以及证据不足的判断继续交给人处理。

产物：带有来源、触发条件、动作、例外和修正信号的规则候选，经人确认后才交给 AI 执行。

通过条件：执行者能根据案例判断是否触发、采取什么动作、何时跳过；规则有接近触发但应跳过的边界案例，并能追溯依据。

## 执行、观察与回溯

先用少量真实案例执行规则。AI 执行任务时也会暴露缺陷，使用产出检查前面的知识。

| 观察信号 | 返回检查 |
| ---------- | ---------- |
| 有一类问题没有任何描述可以覆盖 | 第一步：补充问题维度 |
| 同一规则在不同案例中因术语含义变化而表现不一致 | 第二步：收紧词汇边界 |
| 两条规则频繁冲突，执行者无法决定采用哪条 | 第三步：寻找隐藏的 force 并声明优先级 |
| 规则执行正确但方向错误 | 第四步：回到原始资料核实概念 |
| 结果符合技术要求但不符合领域经验 | 第五步：更换或补充知识框架 |
| 条件范围过大导致执行不稳定，或范围过小导致规则互相冲突 | 第六步：调整 IF 条件的粒度 |
| 知识和规则已经清楚，执行结果仍不稳定 | 执行器：检查模型、工具和运行条件 |

前六行检查知识形成过程，最后一行检查执行器。模式响应未解决声明的问题时，先检查 forces、响应和后果；多个模式之间缺少组合关系时，再检查模式语言。

每轮只修改已有案例、来源或运行结果指向的部分。修改后复查原案例和一个边界案例。需要正式验证假说时，使用 `practice-cognition`。

当前循环可以在以下条件下结束：结果满足当前任务；没有尚未处理的高影响观察信号；仍然存在的不确定内容已明确记录。

## 人与 AI 的分工

人负责：

- 选择真实问题和案例；
- 决定哪些现象值得命名；
- 判断哪些代价可以接受；
- 决定证据是否足以进入框架；
- 选择知识体系并处理冲突；
- 评价结果是否解决实际问题。
- 确认规则候选的含义、触发条件、动作、例外和阈值；

AI 负责：

- 扩展候选维度、词汇和模式；
- 查找来源线索并比较定义；
- 按已确认的框架搜索响应；
- 根据已确认知识起草规则候选；
- 执行规则并暴露边界案例。

表达清楚可以提高执行稳定性。模型能力、资料质量、工具条件和任务性质都是独立变量。规则清楚而执行仍失败时，检查这些变量。

## 输出格式

只保留当前任务需要的栏目，并写清知识产物之间的引用关系。

```markdown
## 当前任务与实践依据

[具体任务、案例、失败产出或观察]

## 领域词汇

| 维度或术语 | 定义与边界 | 正例 | 反例 | 来源状态 |
| ---------- | ---------- | ---- | ---- | -------- |

## 模式

| 情境 | 问题 | 力量 | 响应 | 后果 | 边界 | 来源状态 |
| ---- | ---- | ---- | ---- | ---- | ---- | -------- |

## 模式语言

[知识框架、证据标准、映射、降级、冲突仲裁、未知内容]

## 执行规则

[IF / THEN / UNLESS 规则，以及所引用的词汇、模式和框架]

## 执行反馈

[案例、观察结果、问题所在的知识产物或执行条件、修正内容]
```

用户只需要其中一个阶段时，只输出该阶段及其必要上下文。

## 常见错误

- 没有实践依据就生成完整领域体系。
- 跳过领域词汇，直接要求 AI 给完整方案。
- 把 LLM 生成的术语当成已有领域概念。
- 混用不同体系中的相似词。
- 只记录力量冲突，没有记录模式的响应与后果。
- 把模式语言缩减成孤立规则清单。
- 用固定数字代替尚未完成的判断。
- 把需要人判断的经验全部转换成固定规则。
- 只收集链接，没有核对原始定义和前提。
- 把所有失败都归因于描述，忽略模型、工具和运行条件。
- 只修改当前答案，没有修正产生问题的知识产物。

## 完成检查

结束当前任务前确认：

- 当前任务有具体案例、观察结果或其他实践依据；
- 用户能够用已经定义的词说明问题；
- 每个模式都包含情境、力量、响应、后果和边界；
- 关键概念标明来源状态；
- 模式之间的映射、降级和冲突仲裁已经写清；
- 执行规则没有自行发明阈值，并能追溯到知识产物；
- 结果出错时能定位到知识产物或执行条件；
- 未知内容仍然标为未知。
