# 会话笔记

在当前会话中，把值得保留的信息写入本地 Markdown 笔记。完成重要步骤后更新，自动压缩或手动压缩后重新读取，补充仍保留的对话上下文。

## 存储位置

优先在当前工作目录下选一个隐藏目录，目录名称根据当前任务确定。例如 `./.session-notes/`，仅作为示例，名称不固定。

- 已有适用于当前任务的笔记目录时，读取并继续使用。
- 目录不存在时创建，在其中选择一个 Markdown 文件作为主笔记。
- 主笔记和需要保留的相关材料集中存放在该目录。较长材料单独保存，在主笔记中注明位置与用途。
- 对于已经位于其他位置的项目资源，记录其位置和用途即可，无需复制或移动。

维护笔记时，只修改所选目录中的笔记材料。

记住主笔记的位置。如果能编写压缩摘要，在摘要中注明这个位置，以及压缩后重新读取主笔记的要求。

## 保存什么

只保存同时满足以下条件的信息：

- 与当前事项直接相关，在当前会话后续仍有用。
- 如果压缩后丢失，回答用户或继续工作时，就需要重新查找、调查或重复操作。

记录已经获得的信息。结果、资源位置和时间按实际证据记录；没有证据的内容标注“未知”或“未验证”，取得证据后再更新。

适合保存的内容：

- 用户的重要问题、已经得到的答复，以及尚未解决的部分。
- 当前任务的明确要求和约束。
- 关键决定、选择理由和适用条件。
- 有用的 URL、目录路径、文件路径，以及它们的用途。
- 新安装的工具或依赖、新创建的文件或其他资源，以及后续找到或使用它们需要的信息。
- 关键发现、验证结果和待确认的问题。记录依据，推断明确标注“未验证”。
- 后续能够复用的日志或错误原文。保留足以识别问题、复查结果或继续调查的部分。

保持简短。普通操作、重复输出和与当前事项无关的信息无需记录。已有代码或文档能够直接提供的信息，保留位置和必要说明，避免重复抄写全文。

## 什么时候更新

完成有价值的步骤，或获得影响后续工作的有用信息后，更新笔记。连续获得的一组相关信息可以合并记录，然后继续当前任务。

以下变化也应记录：

- 用户改变当前任务的要求或约束。
- 重要问题得到答复，或关键决定发生变化。
- 完成安装、创建资源，或取得值得保留的验证结果。
- 待确认事项得到证据支持，或原有结论被新证据修正。

知道即将压缩时，补充尚未记录的重要信息。平时也要维护笔记，不要等到收到压缩通知才开始记录。

普通工具调用和重复输出不必每次都更新笔记。已有事项发生变化时，修改对应记录，不要反复追加相同内容。新增会话记录附带时间戳，更新时保留必要的时间信息。

## 笔记分区

按内容需要建立以下分区，有内容时才创建对应分区：

| 分区             | 内容                                           |
| ---------------- | ---------------------------------------------- |
| 当前事项         | 当前目标、明确约束，以及继续工作需要知道的状态 |
| 用户问题与答复   | 值得保留的问题、答复和未解决部分               |
| 决定及理由       | 已选方案、理由和适用条件                       |
| 关键发现与依据   | 有用结论、来源和验证结果；未验证内容明确标注   |
| 安装项与创建资源 | 安装或创建了什么、用途、位置和必要的使用信息   |
| 待确认事项       | 尚未确定、后续需要处理的问题                   |

agent 负责维护整份笔记。用户提供信息时，按保存标准判断是否记录；用户也可以要求记录、查看或修改内容。

## 写入和读取

使用当前可用的普通文件读取、创建和编辑工具：

1. 选择或继续使用适合当前任务的笔记目录。
2. 读取已有主笔记；不存在时创建。
3. 按保存标准添加或更新相关内容，保留仍有用的记录。
4. 用户要求查看时，读取并展示相关记录。

以下仅为笔记内容示例，实际内容和位置根据当前任务决定：

```markdown
## 安装项与创建资源

- 创建了调查报告，保存在 reports/stream-result.md，后续可用于复查流式输入的验证结果。

## 待确认事项

- 未验证：缓存可能与流式输入错误有关，仍需调查。
```

## 压缩后恢复

调用本技能后，在当前会话中持续遵守记录规则。自动压缩或手动压缩后，重新读取主笔记；需要时读取其中引用的材料。

结合压缩后保留的对话与笔记，补充用户问题、决定、发现、资源位置及尚未解决的事项，再继续当前工作。

笔记记录的是此前掌握的信息。与当前对话、文件或工具输出发生冲突时，查证并更新记录。读取笔记不会使未验证的推断成为事实。
