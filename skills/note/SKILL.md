# 会话笔记

在当前会话中，把值得保留的信息写入本地 Markdown 笔记。完成重要步骤后更新，自动压缩或手动压缩后重新读取，补充仍保留的对话上下文。

## 存储位置

优先在当前工作目录下选一个隐藏目录，目录名称根据当前任务确定。例如 `./.session-notes/`，仅作为示例，名称不固定。

- 已有适用于当前任务的笔记目录时，读取并继续使用。
- 目录不存在时创建，在其中选择一个 Markdown 文件作为主笔记。
- 主笔记和需要保留的相关材料集中存放在该目录。较长材料单独保存，在主笔记中注明位置与用途。
- 对于已经位于其他位置的项目资源，记录其位置和用途即可，无需复制或移动。

维护笔记时，只修改所选目录中的笔记材料。

记住主笔记的位置。如果能编写压缩摘要，在摘要中注明这个位置，以及压缩后重新读取主笔记的要求。

## 保存什么

只保存同时满足以下三个条件的信息：

- 与当前事项直接相关，在当前会话后续仍有用。
- 如果压缩后丢失，回答用户或继续工作时，就需要重新查找、调查或重复操作。
- 当前工作树、配置文件或单个只读命令（如 `git status`、`package.json`、目录列表）无法直接给出。

适合保存的四类环境补集内容：

1. **目标与约束**：用户在对话中给出的目标、边界、变更，以及已经答复和尚未解决的问题。
2. **决定与理由**：已选方案、排除其他备选的理由和生效前提。
3. **已验证事实与待查假说**：耗时调查得出的结论、关键错误或日志片段，每条结论旁保留回源指针（如 `src/foo.ts:42` 或复现命令）；没有证据的推断明确标注 `[未验证]` 及下一步验证动作，取得证据后再更新。
4. **压缩后难找回的入口与资源**：有用的外部 URL、宿主机或跨目录绝对路径（如 `/tmp/...`、`~/.omp/...`），以及新安装的工具或依赖、新创建的文件或其他资源和后续找到、使用它们需要的信息（已被 `git status` 或 `package.json` 直接覆盖的常规项目内变动除外）。

保持简短。关键结论旁保留回源指针，避免重复抄写代码或文档全文。

## 什么时候更新

在以下两个时机更新笔记：

- 用户的目标、约束、重要问题答复或方案决定发生变化时。
- 完成安装、创建后续仍需使用的非显式资源，一轮耗时调查得出结论（包括确认某条路径走不通，防止压缩后重走弯路），或收到即将压缩的信号时。

连续获得的一组相关信息合并记录。已有事项发生变化时原地替换旧记录，已解决且不影响后续步骤的事项直接删除。

## 笔记结构与示例

按实际内容需要组织小节，只为当前有内容的类别建立标题。agent 负责维护整份笔记；用户提供信息时按保存标准判断是否记录，用户也可以要求记录、查看或修改内容。

以下仅为笔记内容示例，实际内容和位置根据当前任务决定：

```markdown
## 决定与理由

- 采用流式分块解析（排除一次性读入内存，因为输入文件超过 2GB 时进程 OOM）。

## 已验证事实与待查假说

- 已验证：超时发生在 `src/stream/reader.ts:84` 的 `flushChunk` 调用，复现命令 `bun test test/stream.test.ts`。
- [未验证] 缓存重用可能与流式输入截断有关，下一步检查 `src/stream/cache.ts:31`。

## 入口与资源

- 压测基线产物保存在 `/tmp/stream-bench-baseline.json`，对比脚本为 `~/.local/bin/compare-bench`。
```

## 压缩后恢复

调用本技能后，在当前会话中持续遵守记录规则。自动压缩或手动压缩后，重新读取主笔记；需要时读取其中引用的材料。

结合压缩后保留的对话与笔记，补充用户问题、决定、发现、资源位置及尚未解决的事项，再继续当前工作。

笔记是加速查找的索引，源文件与运行环境才是事实来源。压缩恢复后继续修改代码或下判断前，先按笔记里的回源指针读取对应文件或运行状态，确认结论未过期；若某条已记结论在执行中连续受阻，立即回到源文件或原始命令输出核对，原地修正或删除错记条目。读取笔记不会使 `[未验证]` 的推断成为事实。
