# Help Me Read

把一个或多个 URL 转成可快速阅读的阅读稿。核心目标不是替用户总结文章，而是先给阅读导览，再按需展开原文、必要译文与轻量 commentary。阅读单元默认是自然段；相邻短段或同属一个论证的段落放在一起更好读时，可以合并成段落组。

## 核心原则

| 原则 | 规则 |
|------|------|
| 原文优先 | 每个阅读单元先放原文段落或段落组；不要用总结替代原文。 |
| 必要才翻 | 自动识别用户偏好输出语言；原文不属于该语言时，逐段翻译。 |
| 信达雅 | 译文以“达”为首，先让用户读懂；同时守住“信”，不扭曲原意；再求“雅”，避免生硬机翻腔。 |
| 解读轻量 | Commentary 只辅助阅读，不抢正文；短段通常 1 句，复杂长段可多写几句，但必须帮读者读下去。 |
| 阅读导览 | 在逐段阅读稿之前先给一份导览，答清“核心判断、怎么论证、可信几分”；结构从文章自身逻辑长出来，不套固定栏目。基于已获取全文，不能代替逐段读原文。 |
| 快速阅读 | 关键信息前置，用清楚标题、空行、加粗关键词和编号降低扫描成本。 |

## 执行流程

1. **收集来源**
   - 从用户消息或 `$ARGUMENTS` 中提取全部 URL。
   - 按用户给出的顺序处理 URL。
   - 在写任何 commentary 之前，必须先获取 URL 全文或确认正文完整。
   - 若某个 URL 无法获取全文，明确说明失败 URL 与原因，再继续处理其他 URL。

2. **确定输出语言**
   - 自动识别用户偏好输出语言：优先使用用户明确指定的语言；没有明说时，参考当前会话长期偏好、最近对话中用户要求的输出语言，以及项目/全局指令里的用户交流语言。
   - 不要只看 URL 原文语言来决定输出语言；源语言只用于判断是否需要翻译。
   - 若偏好输出语言仍无法可靠判断，先用用户最近一次自然语言请求所用的语言，并在开头简短标注“输出语言按当前请求推断”。

3. **组织阅读单元**
   - 保留原文的标题、章节标题与段落顺序。
   - 默认以原文自然段为阅读单元；若相邻段落讲清同一个定义、论证、例子、转折或短问答，合并后更符合阅读节奏时，可组成一个“段落组”。
   - 每个阅读单元必须完整保留所覆盖的原文信息，不得因为提炼“核心意思”而漏掉细节。
   - 合并只允许相邻段落；不得跨标题、跨章节或跨 URL 合并；不得重排原文顺序。
   - 合并 2 个以上自然段时，在标题或说明中标明覆盖范围，例如“第 3-5 段”或“段落组：第 3-5 段”。
   - 不确定是否应合并时，保持自然段粒度；用户要求“逐段”时，不主动合并。
   - 若原文一段过长且包含多个明显子段，只有在不删不漏、且明确标注“拆分自同一原段”时才允许拆分；否则保持整段呈现，并在 commentary 里提示“本段含多个子点”。
   - 跳过导航、cookie 提示、广告、重复分享文案、页脚模板与无关推荐；除非用户要求检查这些内容。

4. **先输出阅读导览**
   - 先给每个来源自己的阅读导览；多个 URL 时，必要时再给跨来源对照区。
   - 阅读导览必须从已获取的完整正文中抽取，不引入原文没有的事实；外部背景若确有必要，明确标注“补充背景/未由本文直接证明”。
   - 导览必须答清三个问题：**文章核心判断是什么**、**它怎么走到这个判断**、**我该信几分**。这是常量。
   - 但呈现形式由文章论证形状决定（变量）：小节标题、数量、顺序、合并方式从文章里长出来，不套固定栏目；有则写、无则省、可合并。
   - 先判断文章的主要矛盾，再选导览骨架，可偏离：
     - 驳论文 → 他驳的是什么 / 怎么驳的 / 真相是什么
     - 原理文 → 是什么 / 怎么运作 / 边界
     - 多理由文 → 主张 + 每条理由的强度
     - 叙论文 → 主线 / 关键转折 / 落脚点
   - 核心判断用 1-3 条短 bullet，每条能追溯到正文，不是整篇摘要。
   - 论证路径按原文自身结构走；原文逻辑跳跃时直接指出跳跃点。
   - 可信度（依据、边界、未证明处）按需呈现：可合并成一节、可分开、无可写就省略。
   - 阅读导览不重复整篇摘要；优先输出帮助用户复盘、记忆、判断的信息。

5. **按需展开逐段阅读**
   - 阅读导览末尾给一句自然邀请，例如“要不要继续读原文？说一声就展开”。
   - 不弹结构化二选一、不逼选；用户有明确动作（“继续”“展开”“读”）才展开，否则停在导览。
   - 用户要求只看导览或未回应时，不主动输出逐段阅读稿。
   - 用户选择展开时，继续执行第 6-7 步。

6. **渲染阅读单元卡片**
   - 使用“输出格式”里的固定结构。
   - 先放 **原文**。
   - 只有原文语言不同于自动识别出的偏好输出语言时才放 **译文**。
   - 最后放 **Commentary**。

7. **控制 commentary 轻重**
   - Commentary 聚焦该段作用、关键论点、隐藏前提、上下文转折、术语或阅读提示。
   - 第一句直接给要点，不用“此外”“值得注意的是”这类空转开头。
   - Commentary 篇幅必须明显比原文和译文短：能一句说清就不要写两句，只补阅读所需的判断、语境或提醒。
   - 不展开成长篇背景、独立批评或另写一篇分析；除非用户明确要求。

## 输出格式

每个 URL 按如下格式输出：

导览小节由文章论证形状决定；下方只是骨架示意，不是固定四格。

```markdown
## 来源 1：<网页标题>

<url>

**输出语言：** <自动识别出的偏好输出语言>
<!-- 仅在必要时输出下一行：抓取不完整、输出语言为推断、跳过翻译或来源质量受限。 -->
**说明：** <限制或不确定性>

---

### 阅读导览

<核心判断：1-3 条短 bullet，答“文章想让人记住什么”，每条可追溯到正文>

<论证路径：按文章自身结构走，答“怎么走到这个判断”；原文有跳跃就指出>

<可信度：依据、边界、未证明处按需写，可合并可省略；无可写就删掉这一节>

---

要不要继续读原文？说一声就展开。

<!-- 用户要求展开后，才输出以下内容。 -->

### <原文章节标题>

---

#### 第 1 段
<!-- 或：#### 段落组：第 3-5 段 -->

**原文**

> <原文段落或相邻段落组；合并时保留段落换行>

**译文**

> <仅当原文语言不同于偏好输出语言时输出>

**阅读提示**

<1-3 句轻量 Commentary；先给该段作用、关键论点或阅读提醒；合并段落时说明为何应一起读>

---

#### 第 2 段

**原文**

> <原文段落>

**译文**

> <必要时输出译文>

**阅读提示**

<轻量 Commentary>
```

多个 URL 时重复“来源 N”区块。不同 URL 的阅读导览与逐段阅读单元不要混写成一篇综合叙述；跨来源综合只在每个来源自己的阅读导览之后单独追加。

## 翻译标准

翻译按 **信、达、雅** 执行，但按阅读辅助场景确定优先级：

- **达**：首要目标是让读者一遍读懂。句子要自然、顺口，符合目标语言习惯。
- **信**：保留原文意思、限定词、语气、逻辑关系与不确定性；不得暗中加强、削弱或改写作者立场。
- **雅**：文字干净、有分寸，贴合原文文体，不矫饰、不油滑、不带机翻腔。

直译自然时直译；直译在目标语言中别扭、费解或失真时，改用意译。意译不得增删重要信息，不得改变原文“面貌和轮廓”。

把解释留给 **Commentary**：术语说明、文化背景、双关、典故、歧义与译法取舍，不要塞进译文正文，免得译文变成注释文。

## 阅读设计规则

- Commentary 使用倒金字塔：先给判断或要点，再给必要解释。
- 保留标题，因为标题是扫描阅读的锚点。
- 若原文为了铺垫而把关键结论放在后面，必要时用一句话提醒关键句位置，帮助用户扫描；不要把它做成每段固定模板。
- 只加粗真正关键的术语或转折，不做装饰性强调。
- 如果来源本身结构清晰，就顺着原结构走；不要为了表现分析能力而重排。
- 段落组用于降低碎片化，不用于压缩信息；合并后的原文仍要保留段落换行、限定词、例子和转折。
- 阅读导览可以重建论证逻辑，但必须明确这是导览层；逐段阅读单元仍按原文顺序呈现。
- 可信度判断必须比原文更克制：只解释原文怎么论证的、能推出什么，不替作者补写未说出的结论。
- 每张阅读卡之间用 `---` 分隔；最后一张卡后不加分隔线；章节标题前也放一个 `---` 建立断点。

## 禁止事项

- 不要在能获取全文时只给摘要。
- 不要先给译文再给原文。
- 不要把 URL 原文语言误判为用户偏好输出语言；应按用户偏好输出语言决定是否补译。
- 不要把 commentary 写得篇幅比原文和译文长。
- 不要省略阅读导览；用户明确只要原文/翻译时除外。
- 不要把解释、背景或个人判断塞进译文。
- 不要为了顺滑而改写作者立场。
- 不要重排段落；除非用户明确要 study guide 而不是通读。
- 不要把导览里的逻辑复盘当作重新排序后的正文。
- 不要在阅读导览里加入本文没有支持的事实却不标注来源边界。
- 不要把不相邻段落合并成一个阅读单元。
- 不要用段落组掩盖删节；段落组不是摘要。
- 不要假装抓取成功；抓取失败、只拿到摘要页或只有部分正文时必须明说。

## 完成前自检

- 每个 URL 都已获取全文，或已明确说明为何未能获取全文。
- 每个可用来源都按 URL 独立成块。
- 已先输出阅读导览，答清“核心判断、怎么论证、可信几分”，结构从文章长出来、未套固定四格。
- 阅读导览每条判断都能追溯到已获取正文或已明确标注为补充背景/推断/未证明。
- 阅读导览末尾已给自然邀请；用户未明确要求展开时，不主动输出逐段阅读稿。
- 若用户选择展开，阅读单元卡片遵循 `原文 → 必要译文 → Commentary`。
- 若合并相邻段落，已标明段落范围，且原文信息与段落顺序完整保留。
- 若用户选择展开，原文语言不同于自动识别出的偏好输出语言时，已提供译文；相同时未重复翻译。
- 若用户选择展开，Commentary 篇幅明显短于原文和译文。
- 最终结果帮助用户快速进入原文，而不是把原文交给 agent 解读。
