# 完整重述修正后的回答

修改上一条长回复时，直接交付一份用户无需回看旧消息就能从头读完的完整回答。

## 适用范围

- **需要完整重述**：收到用户纠错、批注或审查意见，修改上一条包含多条结论或结构化小节的回复。
- **直接独立作答**：纯新增问题、与上一条无关的新话题、或单行简短问答的微调。

## 重述步骤

1. **清点仍成立的前提与作废说法**
   动笔前先把上一轮回答中仍然成立的事实、证据、URL 与已经被推翻的前提、分类或结论分开。只保留仍成立的内容进入新稿。

2. **决定沿用原结构还是重排结构**
   - 原结构清晰且分类仍然成立时：保持原有的标题、小节与表格顺序。
   - 原结构本身造成混淆，或核心前提、分类标准已经改变时：按修正后的关系重新组织小节结构。

3. **就地合入修正并同步受影响段落**
   把修正直接写进对应的小节、表格或步骤中，并同步改掉全文所有受该修正影响的上下游表述：
   - **未受影响的内容**：完整保留原有的结论、限定条件、证据与精确 URL。
   - **数字或统计口径修正**：同时写明不同口径对应的数值与条件（例如：`总计 15/30（50%）；排除 X 后为 15/24（62.5%）`）。
   - **事实归因修正**：明确区分「原文明确记载」「基于原文的推断」与「未验证」。
   - **语气与判断力度**：精确化事实、条件与归因，保持原有的明确判断，不把局部修正写成全文软化。

4. **做完整性终检（完成标准）**
   发出前通读全文，确认同时满足以下 4 条可观察状态：
   - 读者只看当前这一条回复，就能拿到全部有效结论、条件与证据，无需向上翻阅旧消息拼凑答案；
   - 已被推翻的旧说法、旧分类或冲突前提已从全文所有小节与表格中彻底清除；
   - 每处修正都已经嵌在它所属的主题位置，正文不出现「修正 1/2/3」「如上所述已修改」之类的补丁说明；
   - 原回复中所有未受修正影响的有效结论、限定条件与 URL 均未遗漏。
