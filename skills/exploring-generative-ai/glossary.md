# Glossary

- **Agentic coding** — coding work delegated to an agent operating with tools and feedback loops. (Ch 13, 18, 25-27)
- **Automation bias** — tendency to favor automated suggestions while discounting contradictory evidence. (Ch 4)
- **Context engineering** — deliberate selection, loading, and maintenance of information supplied to an agent. (Ch 25)
- **Context interface** — a reliable route by which an agent discovers workspace files, specifications, references, or reusable guidance. (Ch 25)
- **Detectability** — likelihood that checks or reviewers will catch an AI-caused problem before harm. (Ch 19, 21)
- **Harness engineering** — design of the tools, instructions, feedback, and controls surrounding an agent. (Ch 26)
- **Impact radius** — how long an agent misstep can remain undetected: time to commit, team iteration, or codebase lifetime. (Ch 13)
- **In-line assistance** — IDE-integrated suggestions while editing code. (Ch 3-4)
- **Local-model viability funnel** — staged evaluation from memory fit through review burden for a local coding model. (Ch 29)
- **Local model** — a model operated locally rather than through a remote hosted service. (Ch 28-29)
- **Multi-file editing** — coordinated edits across more than one source file. (Ch 11)
- **Probability** — likelihood that a task, tool, model, and context combination produces an error. (Ch 19, 21)
- **Reference application** — a current working example used to anchor agent behavior. (Ch 22)
- **Risk assessment** — combined assessment of probability, impact, and detectability. (Ch 19, 21)
- **Spec-driven development** — using specifications as first-class constraints on implementation. (Ch 23)
- **Timebox** — a bounded period for trying assistant interaction before changing approach. (Ch 8)
