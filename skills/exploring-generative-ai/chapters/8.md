# 第 8 章：How to tackle unreliability of coding assistants

- **作者**：Birgitta Böckeler
- **日期**：2023-11-29
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/08-how-to-tackle-unreliability.html

## 核心思想

Coding assistant 以两种代价高昂的方式不可靠：降低代码质量、浪费开发时间。通过校准置信度、建立快速反馈、约束无成效的交互来同时应对两者。

## 可靠性工作流

1. **校准置信度**：问自己，任务、可用 context 与 feedback loop 是否会让错误输出容易被发现。
2. **用证据提升置信度**：当前覆盖薄弱时，用 compiler、测试、linter、review，或要求补充缺失的边界情况。
3. **给探索设 timebox**：assistant 没有足够快地收敛、不值得再花时间时，停止或换方法。
4. **可选：把 persona 当交互辅助**：设定一个受限角色或失败模式来探索；它不提供正确性证据，也不能替代反馈。

## 失败模式

- **反馈慢或含糊**：降低自主性；把任务拆到存在可信检查为止。
- **反复修订仍不收敛**：结束 timebox，回到确定性调查。
- **高置信度的空话，没有证据**：当作假设，而不是结果。

## 要点

1. 快速可信的反馈降低可靠性风险，但不会让输出天然可靠。
2. Compiler、测试、linter 与 review 是互补的置信度信号。
3. 当正确性难以观察，或 assistant 耗时不收敛时，提高警惕。
