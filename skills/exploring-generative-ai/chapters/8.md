# Chapter 8: How to tackle unreliability of coding assistants

- **作者**：Birgitta Böckeler
- **日期**：2023-11-29
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/08-how-to-tackle-unreliability.html

## Core Idea

Coding assistants are unreliable in two costly ways: they can reduce code quality and waste developer time. Manage both by calibrating confidence, creating fast feedback, and bounding unproductive interaction.

## Reliability Workflow

1. **Calibrate confidence**: ask whether the task, available context, and feedback loop make incorrect output likely to be caught.
2. **Raise confidence with evidence**: use compilers, tests, linters, review, or request missing edge cases when current coverage is weak.
3. **Timebox exploration**: stop or change approach when the assistant is not converging quickly enough to justify more time.
4. **Optionally use a persona as an interaction aid**: frame a constrained role or failure mode to explore; it provides no correctness evidence and does not replace feedback.

## Failure Modes

- **Slow or unclear feedback**: lower autonomy; split the task until a trustworthy check exists.
- **Repeated revisions without convergence**: end the timebox and return to deterministic investigation.
- **High-confidence prose without evidence**: treat it as a hypothesis, not a result.

## Key Takeaways

1. Fast, trustworthy feedback lowers reliability risk; it does not make output inherently reliable.
2. Compilers, tests, linters, and review are complementary confidence signals.
3. Increase caution when correctness is hard to observe or the assistant consumes time without convergence.
