# Chapter 4: In-line assistance - how can it get in the way?

- **作者**：Birgitta Böckeler
- **日期**：2023-08-03
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/04-coding-assistance-how-in-the-way.html

## Core Idea

In-line assistants can amplify stale or poor repository examples, while fluent suggestions can trigger review complacency and automation bias.

## Decision Rule

Treat a suggestion as untrusted design input when its surrounding examples are stale, inconsistent, or weak. Independently review the change against current conventions and evidence; do not let prior assistant success lower review depth.

## Anti-patterns

- **Poisoned context**: stale or poor examples bias suggestions toward the wrong pattern.
- **Review complacency**: fluent output makes review feel unnecessary, even though plausibility is not evidence.
- **Automation bias**: accepting an automated suggestion while discounting contradictory human or repository evidence.

## Key Takeaways

1. Improve repository examples and context before trusting suggestions.
2. Review generated code independently, especially after repeated apparent success.
3. Reinforce new conventions explicitly while old examples remain common.
