# Chapter 25: Context Engineering for Coding Agents

- **作者**：Birgitta Böckeler
- **日期**：2026-02-05
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html

## Core Idea

Coding-agent performance depends on deliberately selecting, structuring, loading, and maintaining context. More context is not automatically better; stale or irrelevant context can make an agent guess with confidence.

## Context Management Workflow

1. **Name the task boundary**: identify the current decision, relevant files, constraints, and expected evidence.
2. **Choose a context interface**: give the agent a reliable way to locate workspace files, specifications, reference applications, and reusable guidance.
3. **Decide who loads context**: pre-load essential constraints for deterministic coverage; allow agent retrieval only when the interface is reliable and the risk is acceptable.
4. **Keep context small and current**: remove stale examples, refresh changed references, and add only information needed for the next decision.

## Failure Modes

- **Stale reference**: an example reflects superseded conventions; refresh or replace it before reuse.
- **Missing interface**: the agent cannot discover relevant evidence; provide explicit paths or retrieval instructions.
- **Context overload**: relevant facts are diluted; narrow the task and load less.
- **Illusion of control**: context engineering can improve the chance that an agent loads and follows relevant evidence; it cannot guarantee that behavior.

## Key Takeaways

1. Supply task-relevant context rather than maximum context.
2. Preserve durable constraints and remove stale noise.
3. Treat context design and loading ownership as engineering decisions.
