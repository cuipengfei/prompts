# 第 25 章：Context Engineering for Coding Agents

- **作者**：Birgitta Böckeler
- **日期**：2026-02-05
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html

## 核心思想

Coding agent 的表现取决于刻意选择、组织、加载与维护 context。context 多并不自动更好；过期或无关的 context 会让 agent 自信地瞎猜。

## 上下文管理工作流

1. **划定任务边界**：确定当前决策、相关文件、约束与期望证据。
2. **选择 context interface**：给 agent 一条可靠的路径去定位 workspace 文件、specification、reference application 与可复用指导。
3. **决定谁来加载 context**：预加载关键约束以获得确定性覆盖；只有 interface 可靠且风险可接受时，才允许 agent 自己检索。
4. **保持 context 小而新**：移除过期示例，刷新变更过的引用，只加下一次决策所需的信息。

## 失败模式

- **过期 reference**：示例反映的是已被取代的约定；复用前先刷新或替换。
- **缺失 interface**：agent 找不到相关证据；提供显式路径或检索指令。
- **Context 过载**：相关事实被稀释；收窄任务，少加载。
- **控制的错觉**：context engineering 能提高 agent 加载并遵循相关证据的概率；它不能保证那个行为。

## 要点

1. 提供任务相关的 context，而不是最大量的 context。
2. 保留持久约束，移除过期噪音。
3. 把 context 设计与加载归属当作工程决策。
