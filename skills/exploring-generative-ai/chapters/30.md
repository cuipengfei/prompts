# 第 30 章：The Economic Benefit of Refactoring

- **作者**：Giles Edwards-Alexander
- **日期**：2026-07-30
- **来源**：https://martinfowler.com/articles/exploring-gen-ai/refactoring-economic-benefit.html

## 核心思想

在 agentic codebase 里，重构有可衡量的经济收益：现在花在重构上的 token，会降低未来每一次变更的 token 成本。因为 agent 从不学习，同一个代表性变更可以在每次重构步骤后由全新的 sub-agent 重跑——这是对人不可能做的受控实验。

## 实验

- 一个约 150 kLoC 的应用（主要是 Rust），完全由 agent 编写，人类几乎不 review。
- 数据访问层长成了一个 17,155 行的单一文件——一个有清晰接口的独立模块：理想的重构目标。
- 方法：规划严格的重构序列；把一次代表性变更定义为单个 prompt；在每次重构步骤后，测一个全新 sub-agent 完成该变更的 token 成本，每次都丢弃该变更。

## 结果

- 每次相同变更的输入 token 从 **159,564 降到 27,360——节省 83%**——而且这个节省在之后每一次触及该层的变更上都会复现。
- 节省来自 agent **读的代码更少**，而不是代码更少：层总大小大致不变。收益取决于 agent 识别出最小的相关文件子集——把大文件随机拆成小文件达不到这个效果。
- 输出 token（写出的代码）几乎没变；生成的非确定性掩盖了分解带来的任何差异。
- 决定性的下降来自最后分解成内聚文件——由前面所有局部抽取步骤铺垫，正如重构通常的推进方式。

## 过程观察

- Agent **不擅长选择重构**：必须由人主动指导哪些重构适用。它也不**擅长机械地应用**重构（grep/sed 脚本被缩进搞混），而且第一轮错过了最有价值的一步。
- Harness 里显式的「重构步骤」本身并没有促使 agent 改进文件——漂移照样积累。
- Token 计数警示：工具没有可靠的实时 token 计数；实验用字符数近似 token。

## 要点

1. 重构现在可以量化为投资：花一次 token，在未来的每次变更上省钱。
2. 把最大文件大小与 files-touched-per-change 趋势当作 agentic 代码漂移的早期预警信号。
3. 重构质量仍依赖人的指导——无论是选择还是验证重构。
4. 用全新 agent 做受控实验，是测量 codebase 质量效果的新可靠方式。
